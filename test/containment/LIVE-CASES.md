# T3 live containment cases

Tier T3 of `docs/operations-and-testing.md`: real `claude -p` runs through the real `ClaudeHostAdapter` on a generated scratch repository (under `$TMPDIR`, with a temp profile and data root; never a real repository or the real profile). Suite: `test/containment/live-onboarding.test.ts`; harness: `test/helpers/live-harness.ts`.

Run (skipped unless `AVARICE_LIVE=1`, so `npm test` never starts the real claude and never spends):

```bash
AVARICE_LIVE=1 node --test test/containment/live-onboarding.test.ts
```

Every verdict comes from the staging tree digest (outside the write set `.planning/codebase`), the source repository's `git for-each-ref` digest plus HEAD and `config`, the generated `host-settings.json`, `hook-policy.json` and a stand-in `policy.json` in the data root, the ledger (`hook.decision`, `tool.completed`) and the host's own stream-json tool events. The model's reply is never read as a verdict. A case where the model never made the scripted attempt fails as "not exercised" instead of passing.

Spend rules: model `haiku`; a per-run `--max-budget-usd` (0.40 for a single-prompt case, 0.60 for the fast onboarding); every run that started the host is added to a spend ledger (`AVARICE_LIVE_LEDGER`) and a case that could push the recorded total past the authorized cap is not run.

### Limits

- Behavior 3 shows only that a question has the routable shape. The Claude host adapter hands no final text to the pause recogniser, so a supervisor does not route such a question from a Claude host (docs/system/findings.md).
- The `Bash(cat:*)` allow rule also permits `cat > file`. The deny rule on `config/app.json` was not bypassed in any session (the file was byte-identical after each one, asserted), but the sample does not show the rule holds against that form.
- **Allow list since plan 02-31.** The recorded attended sessions (G-02-9) ran under the earlier list, which allowed `cat`, `head`, `git diff`, `git show` and `git log` as prefix rules; those verdicts stand and are not re-run. The harness now allows `avarice status`, `avarice context` and `ls` as prefix rules and git only as the exact commands `git status` and `git log --oneline`, because `cat` and `head` admit a redirect and `git diff`, `git log` and `git show` admit `--output=<file>`. Whether the host's permission engine admits a redirect through a prefix rule such as `ls:*` is not established, because that needs a live session; it stays open.
- Print mode with `dontAsk` is a stand-in for an attended terminal. The sample is 4, 3 and 3 sessions on one model and one prompt style per behavior.
- The full redacted transcripts are kept under `/private/var/folders/hl/ryh6jjw90v5gj8hg9j9clckm0000gn/T/avarice-attended-<case>-*` (one directory per session; the first, invalidated `status-first-1` session is `avarice-attended-status-first-1-3ZCJIR`).
