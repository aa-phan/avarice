# Processes

> Status: drafted, not yet reviewed.

This document describes the two end-to-end flows of the onboarding slice, `avarice onboard` on a brownfield repository and `avarice resume` after a kill during the map invocation, as traced through the CLI commands, the application stages and the host, hook, GSD and graphify adapters (`src/cli/`, `src/app/`, `src/adapters/`, `src/hook/`).

Onboarding is one lease-holding pass through a fixed list of stages. The first stage that cannot proceed stops it in a named state: incompatible when GSD is missing or out of range, blocked when the host cannot enforce containment, when a budget is spent, when validation fails twice, or when the staging tree holds writes outside every write set. An index that cannot be built never stops it. A kill leaves the host running and the lease held, so resume works only after the lease expires. It then ends the host by its session ID, lets the files in staging decide whether the map invocation finished, and either validates them or launches the map again. The points to watch where two documents meet are listed under "Things to look out for at the hand-offs".

## Onboard a brownfield repository

The flow is drawn in [onboard.puml](diagrams/onboard.puml). The command ends with exit 0 only when the project is active; every other ending is exit 3, and a failure of the run itself is exit 70 ([cli-reference.md](cli-reference.md#onboard)).

1. The operator runs `avarice onboard --policy onboarding` with the repository path. Flags are checked first, so a bad mode or a malformed budget registers nothing ([cli-reference.md](cli-reference.md#onboard)).
2. Startup opens the ledger, locates GSD and the graphify binary, and chooses the host. The contained host is chosen only when an admitted GSD, a `claude` executable, the GSD shim preamble, the hook script, a working sandbox and an admitted host version are all present. Otherwise a refusing host is used, and the reason is stored in its descriptor ([integrations.md](integrations.md#the-unavailable-host-fallback), [config-reference.md](config-reference.md)).
3. Registration and preflight read the repository from git objects at HEAD, pin that commit, and record names and classifications only. An active record, or another onboarding past its first state, refuses the command with exit 3. An onboarding still at its first state is continued, not duplicated ([onboarding.md](onboarding.md#preflight-and-refusals)).
4. The command takes the lease on the onboarding and starts the stage loop ([onboarding.md](onboarding.md#stage-loop-and-leases)).
5. Contract stage: GSD must be present and in range, otherwise the onboarding ends incompatible before any contract or staging exists. Then the contract is compiled, stored with its budget rows, and the onboarding moves to the contract-proposed state ([onboarding.md](onboarding.md#contract-compilation-and-budgets)).
6. Workspace stage: a local clone is made at the pin under the work root, GSD is probed, the mapping mode is decided, and GSD is configured in staging. Then the host's declared enforcement is read. A host that does not report enforced ends the onboarding blocked with reason enforcement failure, with the clone and the GSD settings already in place and no map launch made ([onboarding.md](onboarding.md#staging), [onboarding.md](onboarding.md#enforcement-check)).
7. Map stage: unless the mode is skip, the invocation budget is reserved (one invocation unit, the smaller of the wall-clock share and what remains, the smaller of the per-invocation cap and the remaining cost), and the launch is recorded as started with a fresh session ID. A refused reservation ends the onboarding blocked with reason budget exhausted ([onboarding.md](onboarding.md#mapping), [containment.md](containment.md#budgets-and-reservations)).
8. Launch assembly generates five inputs in a private directory, proves the launch checks, judges the launch line, and starts the host detached in its own process group with a scrubbed environment and the wall clock enforced by AVARICE. Any refusal before the spawn blocks the onboarding with reason enforcement failure ([containment.md](containment.md#how-a-launch-is-assembled), [integrations.md](integrations.md#claude-code)).
9. During the run, every tool call goes through the PreToolUse hook. An allowed call is charged to the shared run budget in the same ledger transaction that records the decision: tool calls for ordinary tools, the subagent total for agent calls. A denied call is charged nothing. A call that finds its budget spent is denied as budget exhausted ([containment.md](containment.md#the-pretooluse-hook)).
10. When the host exits, the invocation settles: the unit, the measured duration and the reported cost are charged, and the transcript is stored redacted. The ending is classified from measured facts, never from model text. A hook deny for a spent budget during the invocation overrides the host's own outcome ([onboarding.md](onboarding.md#mapping), [integrations.md](integrations.md#outcome-classification)).
11. AVARICE stamps the map itself through GSD after progressed, no-progress and inconclusive endings, because the mapper's own stamp call is denied by the hook. Progressed and inconclusive endings go to validation; denied, failed and no-progress endings block with reason decision; budget exhausted blocks with that reason ([onboarding.md](onboarding.md#mapping)).
12. Validation runs seven checks over the staging map. Accepted moves on. A secret hit blocks at once. Any other failure sends the onboarding back to mapping once and then blocks ([onboarding.md](onboarding.md#validation-and-the-retry-rule)).
13. The three index steps run in order: code graph, intel, knowledge. graphify is run by AVARICE through the sandboxed executor, never from the host. Intel and knowledge each take one more contained invocation under the same hook and budgets, and AVARICE then finishes each step itself. A step that fails is recorded as absent with a reason and never blocks ([indexes-and-context.md](indexes-and-context.md#the-index-steps)).
14. Activation re-checks the whole staging diff against the write sets, stores the map documents and a manifest, and inserts the project record and moves to active in one ledger transaction ([onboarding.md](onboarding.md#activation), [data-model.md](data-model.md#project-record)).

## Kill during the map invocation, then resume

The flow is drawn in [resume-after-kill.puml](diagrams/resume-after-kill.puml).

1. The supervisor is killed with no cleanup. The launch row stays started with its session ID, one invocation unit stays reserved, and the lease stays recorded until it expires. The host runs on detached, and the hook keeps charging the run's tool-call budget for calls the orphan makes ([containment.md](containment.md#session-id), [data-model.md](data-model.md#leases-and-optimistic-concurrency)).
2. The operator runs `avarice resume` with the onboarding ID. A stopped onboarding is reported without taking the lease. A live lease refuses the command with exit 3; `status` shows the onboarding as interrupted once the lease is absent or expired. The lease lasts up to 180 seconds after its last renewal, so the orphan can run for that long before anything can end it ([cli-reference.md](cli-reference.md#resume), [onboarding.md](onboarding.md#stage-loop-and-leases)).
3. Once the lease has expired, the takeover succeeds and raises the fence, so a late write from the dead holder is refused ([data-model.md](data-model.md#leases-and-optimistic-concurrency)).
4. Reaping comes first. Every launch row left started is looked up by its session ID in the process table; the whole process group is terminated, then killed after a grace period. A process that survives, or a failed search, fails the resume with exit 70 and leaves every row started. A host without a reap capability skips this step silently ([integrations.md](integrations.md#reaping-by-session-id), [onboarding.md](onboarding.md#resume-reconcile-and-reaping)).
5. Reconcile reads the map files in staging. If more launches than validations exist and every required file is present, the launch is marked reconciled, AVARICE stamps the map, and the onboarding goes to validation with no second launch. Otherwise the launch is marked interrupted and the map stage launches again ([onboarding.md](onboarding.md#resume-reconcile-and-reaping)).
6. The next reservation converts the dead reservation to spent, charging it the cost it was allowed to use, and appends a warning event. No wall-clock time is charged for it, and nothing is refunded, including tool calls the orphan made. In the reconciled branch the next reservation is the intel invocation. In the relaunch branch it is the map relaunch, with a new session ID ([containment.md](containment.md#budgets-and-reservations)).
7. The loop continues as in the onboard flow from validation (or from the relaunched map) to activation. Registration, the contract and the workspace stage do not run again, because the committed state is already past them ([onboarding.md](onboarding.md#resume-reconcile-and-reaping)).

## Things to look out for at the hand-offs

- **Where an unavailable host stops the run.** A missing GSD stops at the contract stage as incompatible. A missing or unusable host does not: the contract stage passes, the clone and GSD configuration are made, and the workspace stage then blocks with reason enforcement failure ([onboarding.md](onboarding.md#enforcement-check), [integrations.md](integrations.md#the-unavailable-host-fallback)).
- **graphify and the host.** The host's search path never includes graphify. The knowledge pass runs no shell and no skill, and AVARICE runs graphify itself for the code graph and for clustering ([config-reference.md](config-reference.md), [indexes-and-context.md](indexes-and-context.md#the-knowledge-pass)).
- **Who charges what.** The application layer charges invocations, wall clock and cost, around each invocation. The hook charges tool calls and subagents during it. All five budgets are per run, shared by the map, intel and knowledge invocations and by a resumed run ([containment.md](containment.md#budgets-and-reservations)).
- **The concurrency deny is not a budget deny.** A subagent refused for concurrency is recorded as a hook deny but does not count as budget exhausted, so it never overrides an outcome ([containment.md](containment.md#subagent-limits)).
- **Resume cannot reap before the lease expires.** A resume inside the window exits 3 and ends nothing ([onboarding.md](onboarding.md#stage-loop-and-leases)).
- **Reconcile judges presence, not quality.** It decides from the required files existing; validation then judges their content ([onboarding.md](onboarding.md#resume-reconcile-and-reaping)).
- **Resume with a refusing host.** The reap is skipped, so a survivor from an earlier environment is not ended before the staging files are read. A needed relaunch is refused by the host and surfaces as a failed run (exit 70), not as a block. The invocation unit is spent each time ([integrations.md](integrations.md#reaping-by-session-id)).
