# Phase 03 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

The register below is the union of the `<threat_model>` blocks of all 74 plans in this phase (224 unique threats; `T-03-SC`, the no-package-installs threat, is repeated in every plan and listed once). No SUMMARY.md raised a new threat flag. Each `mitigate` threat was checked against the code at ASVS level 1 by `gsd-security-auditor`; the evidence column cites what it found.

### Audit notes

- **T-03-196 is open, medium, non-blocking.** The hook judges a Grep or Glob `path` against the read rules, but a relative Glob pattern with `..` segments, or a `{…}` alternative holding an absolute path, gets no pattern-root check (`src/domain/hook-decision.ts:140-143`, review WR-05). Glob returns names, not contents, and the sandbox `denyRead` still applies. Fix: compute the pattern root for every Glob pattern and refuse `..` segments and absolute brace alternatives.
- **Owner identity (review WR-02).** Fourteen high threats whose actor is Claude acting for the owner are closed on their procedural checkpoint, with the residual logged as AR-03-06. For threats whose actor is a contained run (T-03-08, T-03-26, T-03-38, T-03-46), the sandbox's deny on the data root and ledger (`src/domain/invocation-scope.ts`, `settings.ts:124-125`) backstops the identity walk independently.
- **Not a threat in this register:** `contract amend` makes no `ownsProfile` check, unlike `decide`, `cancel` and `schedule`. It is already recorded at `docs/system/findings.md:258`.
- The auditors re-ran the pinning suites at HEAD (about 2,200 unit, integration, fault and scenario tests, all passing). They also recomputed `exitVerdict` from the evidence files, which reproduced `exit: 3/3 ready_for_review`.
