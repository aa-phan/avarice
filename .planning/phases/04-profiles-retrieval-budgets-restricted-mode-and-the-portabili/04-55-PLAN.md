<objective>
Close WR-11: the whole-file read caps are not enforced by anything a run does. The contract, the budget rows, `doctor` and the retrieval guard's header present `retrieval.fullReads` (20 files) and `retrieval.fullReadBytes` (256 KiB) as per-run caps, but the hook charges a Read to `toolCalls` only and the guard's `beginRead` has no caller outside tests, so both rows are created and never spent (recorded at docs/system/findings.md:283). This plan makes the hook charge every Read of a run to both rows, at D-09's values, in the transaction that already charges `toolCalls`.

Purpose: progressive retrieval with enforced caps (phase goal, CON-10, CON-11). A run can no longer read without limit while its contract says it cannot.
Output: the two rows charged and enforced by the hook, two spent rules, tests at and one past each cap.
</objective>
