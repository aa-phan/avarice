<objective>
Profile configuration read back, migration 0004 and store scoping (SEC-1, SEC-4, OPS-5, FR-12, D-18). Today config.json is written once and never read (findings 24-25), roots can drift from it, and nothing checks that the opened store belongs to the selected profile. This plan parses the whole config, makes it authoritative for roots, adds migration 0004 (status indexes, approvals index and guard triggers), asserts meta.profile_id at open, backfills bindings for existing projects, and exposes the parsed config and the policy sources on AppDeps.

Reversibility note: migration 0004 is costly (Phase 5 backup and restore depend on the schema); the owner already decided D-18, so no checkpoint is inserted.
Output: config parser and reader, migration, composition wiring, tests.
</objective>
