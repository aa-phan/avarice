  - "GWR-02 is fixed fail closed, not by expanding: an 'expansion word' is a word holding, outside quotes and not after a backslash, a brace group (a `{` with a later `}` and a `,` or `..` between them) or a glob (`*`, `?`, or a `[` with a later `]` in the same word). A lone `[` (the test command), `{owner}` (gh api placeholders, no comma) and the reserved words `{` and `}` are not expansion words. The scanner records which words are expansion words without changing any word's text."
  - "Where an expansion word makes a command unparseable: (1) the program word or any word before it (an assignment, a reserved word, a wrapper, a wrapper's option or operand); (2) for git, any global option and the subcommand word; for gh, the group, any option before the subcommand and the subcommand word; for npm, any word up to and including the subcommand, or any word when no subcommand is found; (3) a brace-expansion word anywhere in a command that is privileged, because the bound parameters would not be the words the shell runs. A glob after the subcommand of a privileged command stays bound as its literal text and is named in the residual list, because its expansion depends on the files present. Brace words in other programs' arguments (`mkdir -p src/{a,b}`, `git add src/{a,b}.ts`) stay none, so ordinary owner commands are not refused."
  - "The differential oracle treats an 'unparseable' answer of classifyLine as covering every privileged invocation of that line, because both callers refuse an unparseable line; a line the oracle runs must still be either classified with the action or refused."
  - "GIN-02 wrappers and launchers, each read as the real program reads its arguments: doas (like sudo, -u and -C valued), taskset (options, then one mask or list operand; -p with no command runs nothing), arch (-arch and -e and -d valued, the -arm64 and -x86_64 style flags skipped), caffeinate (-t and -w valued), unbuffer and chronic (flags only), coproc (a reserved word: the program is the next word), find (-exec, -execdir, -ok and -okdir run the words up to `;` or `+`, each occurrence), parallel (the words before `:::` or `::::` are a command string run through a shell; with none, each argument after `:::` is a command string), watch (the words after its options are joined and run through a shell, or run directly with -x or --exec), su (the value of -c, --command or --command= is a shell string), trap (with two or more operands the first is a shell string; one operand or `-` runs nothing), and a here-string (`<<<`) given to a shell with no -c string and no script operand, whose text is the shell's input."
  - "What remains is named in the privileged-approval row's bypass text and the classifier's header comment: pathname globbing in the arguments after a privileged subcommand; arguments a wrapper reads from standard input (xargs, parallel fed from a pipe); interpreters running a code string (node -e, python -c); other programs that run commands (make, ssh, script, expect); a git alias set by an earlier separate call; and git config files named on the line (GIT_CONFIG_GLOBAL, GIT_CONFIG_SYSTEM, GIT_CONFIG), which are bound as env but whose content is not read."
