<objective>
`status` under 300 ms with 1,000 runs (AC-2, SC2). Research measured a median of 924 ms: getRunStatuses issues nine queries per run, and three tables had no run_id index (now added by migration 0004). This plan adds one batched ledger read for every per-run table, rewires the status read model to it with byte-identical output, and adds the bench script and a statement-count guard.

Purpose: AC-2 passes and stays passing as runs accumulate.
Output: ledger batch read, status rewiring, bench script, guard test.
</objective>
