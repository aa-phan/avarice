Purpose: the root cause in 01-UAT.md is binding. It has three parts: (1) the prompt makes claude-haiku-5-5 build each read path itself, and the model sometimes drops the `.avarice-knowledge/` segment (2 of 4 live runs); (2) nothing gives the model a way to recover (the plan holds repository-relative paths that also exist as originals, the denial is bare, and the prompt says to skip the file and go on); (3) nothing accounts per document (a shape-valid empty chunk counts as usable, the corpus is derived from chunk shape, validation needs only one document node, and `dropped` counts only edges).

## Mechanism choice (chosen and rejected)

The UAT `missing` list and the debug session's fix directions are example routes, not binding. This is the smallest set that closes the gap in full. Plans 01-25 and 01-26 share this section; plan 01-26 refers to it.

Chosen:
- **A. Per-document accounting (Task 1).** After the merge, AVARICE checks each manifest entry for a document node of the pass that cites it. The record gets `knowledge.documentsExpected` and `knowledge.dropped.unread`, and `knowledge.corpus` is built from covered documents. `AssembledExtraction.usedFiles`, the list derived from chunk shape, is removed (Task 2) so that coverage cannot be derived from chunk shape again. This answers root cause 3.
- **B. Coverage rule in validation (Task 1).** Fewer than half the manifest's documents covered is `validation-failed`, and the graph stays code-only. This replaces "one document node is enough". It keeps the "at least half" number that owner decision B applied to chunks, now measured on documents, the unit the record states. The rule for chunk files that do not parse stays as the early exit, with its per-chunk reasons. Root cause 3.
- **C. Verbatim paths in the plan (Task 2).** Each file gets an absolute `readPath` and each chunk an absolute `writePath`, written into `.chunks.json` as data. The prompt tells the model to pass them exactly as given and never to build a path. `path` stays only as the `source_file` citation. Root cause 1, the trigger.
- **D. Recovery rule in the prompt (Task 2).** A denied or failed read is retried once with the `readPath`, then the file is left out, and the per-document accounting counts it unread. This replaces the sentence that told the model to skip the file. Root cause 2.
- **E. Live gate (plan 01-26).** assert-exit fails when the record lacks the accounting or has any unread document. It is checked at zero unread, not at the share: the share is the stage's admission rule, which validation already enforces, so an assert at the share would re-check the code under test. UAT 154 says every corpus document becomes a node.
- **Fake-host reproduction (Tasks 1 and 2).** `FakeKnowledgeHost` gets a `perDocument` mode that reads originals from a given chunk on, judges each read with the hook's first read rule, and writes empty chunks for denied files.

Rejected:
- **Chunk usable only when its files yield document nodes.** This judges chunk files, not documents. The merge unions by ID, so a document's node may arrive in any chunk file (the fake host's default writes every node into chunk 1). Coverage on the merged graph does not depend on which chunk carried a node.
- **Hook deny reason naming the allowed corpus root.** The root is already the prefix of every `readPath` in the plan, and rule D points the retry at the `readPath`. Changing the text would touch the fail-closed hook that every purpose shares, along with its 150 ms p95 budget and its deny-output tests, and would add no information.
- **Counting the invocation's hook denies in the step result, or reordering `classifyOutcome`.** A deny count is neither necessary nor sufficient for coverage: a denied exploratory Glob loses nothing, and a model that never asks for a file loses it with 0 denies. The count is already in `invocation.finished.hookDenies`. Reordering `classifyOutcome` would also change map and intel, whose live runs progress with 15 to 19 Bash denies each (01-19 evidence).
- **The absolute `.chunks.json` path in the prompt.** The prompt is fixed text and two counts, and a unit test pins it as identical across plans. All four live runs read the plan file at the right path; it is one fixed name in the working directory, read before any slip.
- **Dropping the relative `path` from the plan.** `source_file` would then be an absolute machine path in every node and edge of graph.json. The merge maps nodes back, but edges would keep the path.
- **Recording the merge's `malformed` counter.** A malformed node of a document leaves that document without a node, so `dropped.unread` already counts the loss.
- **Out of scope:** the map invocation's 2 Bash `outside-read-set` denials (a side note in the debug session).
