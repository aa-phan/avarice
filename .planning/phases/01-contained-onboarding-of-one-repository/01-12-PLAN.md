Build AVARICE's own enforcement layer inside the host: the fail-closed PreToolUse hook (plus PostToolUse attribution and ConfigChange refusal) and budgets that persist across retries and restarts.

## Phase Goal

**As a** solo developer, **I want to** onboard one existing repository into AVARICE, **so that** later unattended runs start from an active project record with a code-and-document graph.

Purpose: the Edit tool is not sandboxed (pre-slice spike), so file-tool limits rely on rules plus this hook; command identity under the owner's Bash strategy lives here; ONB-8 and CON-13 require budgets that survive kills. The hook must stay inside the 150 ms target (research measured 79 ms on Node 22.22.3 for the core work).
Output: hook decision domain, lean hook entry, hook-policy writer, budget methods and settlement, S-35 suite, hook benchmark.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host → hook process | Tool inputs are model-controlled JSON on stdin |
| hook → ledger | Concurrent hook processes (parallel subagents) write the same rows |
| CLI flags → budgets | The user may lower budgets at start |

| T-01-32 | Elevation | Bash identity rules | high | mitigate | Preamble hash plus read-verb set; no compound operators, redirections or substitutions; denied prefixes; sandbox confines whatever slips through |
