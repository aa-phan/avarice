<objective>
Close UAT gap G-02-9. Run the installed `avarice-run` skill in real attended Claude Code sessions and judge, deterministically from each transcript, the three behaviors the skill asks for: call `avarice status` first, stop on a denial, and phrase a consequential question in the shape the supervisor recognises. Every session is spent through the Phase 2 ledger under the 25 USD ceiling (D-15). Each runs on a generated scratch repository (D-07's pattern) with a throwaway profile under the default parents.

Why the verdict can be deterministic: each behavior is defined on structural facts. Behavior 1 is the order of tool calls and the call's success. Behavior 2 is the host's own denial records, the tools called after the first denial, and a tree digest. Behavior 3 is the production pause recogniser's verdict on the final message plus a file digest. The model's behavior is stochastic, so each behavior is sampled (4, 3 and 3 sessions, the proposal's ten scripted attended sessions) and passes only when every judged session passes. The owner reviews the recorded evidence at the end-of-phase check.

Two limits are stated, not hidden. First, print mode with `--permission-mode dontAsk` stands in for an attended terminal: no person answers prompts, and the denial comes from a permission rule. Second, behavior 3 shows the question has the routable shape. It cannot show that a supervisor routes it, because the Claude host adapter hands no final text to the recogniser (claude-host.ts sets no `question`). This is recorded as a finding.

Purpose: the owner asked for this effect to be tested (UAT test 9, coverage 02-15/D6).
Output: the attended harness and suite, the recorded sessions, LIVE-CASES.md records, docs/system findings and recount.
</objective>
