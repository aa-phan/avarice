<objective>
Close UAT gap G-02-10 with a dedicated offline fault test: a supervisor holding a stale lease fence cannot commit the `discard-attempt` checkpoint or discard the workspace, on both code paths that reach the discard (the crash-and-retry path of the running stage and the resume prelude), with the adjacent lease edges and the one window the fence cannot cover (a supervisor superseded after its checkpoint, during the restore) characterized and proven to converge.

The gap is missing verification, not a known defect. Reading the code shows one defect the specified test will reveal: on the resume path the reconcile prelude records a failed `resume:reconcile` step after the fence refused it (src/app/run-resume.ts reconcileRun), so a superseded supervisor writes a ledger row after its fenced write failed. docs/system/data-model.md says a superseded supervisor records unfenced rows only "until its next fenced write fails". The plan fixes this test-first.

Purpose: the owner asked for a dedicated stale-fence discard test (UAT test 10, coverage 02-16/D9). Offline fault suites come before live work, following the phase pattern (D-07). The supervisor is driven through `runSupervisor` with the `reconcileRun` prelude, the same composition the detached `supervise` process uses (D-18).
Output: test/fault/run-discard-stale-fence.test.ts, the fenced reconcile record, docs/system updates, RED evidence files.
</objective>
