<objective>
Close two code-review findings of 02-REVIEW.md (triage group P2, budget settlement):
- R-WR-05 (WR-05): chargeOrphans makes three separate ledger writes (invocations from the reservation, cost, the event). The orphan count is read from `reserved`, which the first write sets to 0, so a kill between writes loses the cost for good. settleInvocation has the same shape, which the review did not name: a kill after its first write leaves the reservation spent with time and cost never charged. Fix: one ledger method that applies a list of charges and an optional event in one transaction, used by both. SqliteLedger is the only Ledger implementation.
- R-WR-04 (WR-04): wasKilled treats only a timeout or a signal as killed. A host that exits with no result event reports cost 0 and is charged 0, on exactly the CON-16 crash path. Fix: an outcome with `resultSeen === false` is killed for cost, so it is charged its reservation. The clean exit with no result counts the same, because its cost is unknown too. Consequence to name: a host that fails at startup now charges a full per-invocation cost reservation; its invocation unit is spent anyway.

Order (triage): the transactional method lands first (Task 1), so the new charge in Task 2 goes through it.

docs/system/containment.md is also edited by plans 02-27 (wave 1) and 02-33 (wave 3), so this plan runs in wave 2. docs/system/findings.md's open line on an orphan's uncharged wall clock is not changed: the new method keeps that behavior, and the decision is the owner's.
