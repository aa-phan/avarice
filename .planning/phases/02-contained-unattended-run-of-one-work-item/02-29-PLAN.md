<objective>
Close four code-review findings of 02-REVIEW.md (triage group P4, the git adapters, plus the run-ref finding of the exit evidence script):
- R-WR-06 (WR-06): the adapters accept 40- or 64-hex commit ids while `revisionOf`, G4 and the Phase 1 modules accept 40 only, so a SHA-256 repository passes the first reads and fails later. Fix chosen (triage): narrow the shared pattern to 40 hex and refuse a SHA-256 HEAD at the first read with a message naming the object format. Widening six domain patterns would buy nothing while onboarding cannot map such a repository. Start maps a head error to its internal exit (70) with that message, before any row or file is created; no new refusal code is added.
- R-WR-07 (WR-07): `Math.min(...times)` throws RangeError above about 125000 commits. A loop or reduce replaces the spread.
- R-IN-04 (IN-04): checkRelative splits on `[\\/]`, so a POSIX file named `a\b` is acted on as `a/b`. The product is macOS-only, so a backslash is a literal character; split on `/` only.
- R-IN-09 (IN-09): `RUN_REF_GLOB` becomes `.*` and crosses `/`, so extra refs under the run prefix leave the refs digest. An anchored single-segment pattern replaces it for `--allow-run-refs`. The review's second suggestion, asserting `refsAllowed <= 1`, is not added: the Phase 2 exit evidence tool already fails any new ref other than `refs/heads/avarice/<runId>` (scripts/exit-run-phase2-tools.ts about lines 699-706). Plan 02-35 records that reason.
