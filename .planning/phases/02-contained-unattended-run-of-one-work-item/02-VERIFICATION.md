```

git show :.env                 => allow shell-identity
git log -p                     => allow shell-identity
cat .env                       => deny  deny-secret-read
git show HEAD:certs/server.pem => deny  deny-secret-read   (by accident: the '/' splits the operand)
```

Weighing against the requirements:

- CON-2 and CON-8 are about writes and path canonicalization for write scope. CR-01 is a read-confidentiality bypass, so it does not falsify them. Writes outside scope stay blocked (hook, Seatbelt, G2/G4 gates, live cases).

A critical, reproduced bypass of an enforced control, with no test, no documentation of the limit and no triage, is not something to ship under that claim. It is a contained fix (one function, three tests, one doc line) or an explicit documented acceptance.

I classify it BLOCKER. It does not undo any success-criterion evidence above.
