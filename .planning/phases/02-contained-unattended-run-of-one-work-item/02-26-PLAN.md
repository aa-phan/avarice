<objective>
Close verification gap CR-01: the secret-glob read denial (`deny-secret-read`) is bypassable through the admitted git read commands. Verification reproduced it at HEAD: with denyReadGlobs `['**/.env','**/*.pem']`, decideToolCall allows `git show HEAD:.env`, `git show :.env` and `git log -p` (rule `shell-identity`) while `cat .env` is denied. The operand `HEAD:.env` is judged as the clone path `<clone>/HEAD:.env`, which no glob matches, and `git log -p` has no operand to judge.

The fix closes the whole class "an admitted git command prints tracked or staged content of a secret path", not only the three repro commands. Among the eleven admitted read-only commands, five are git: `git ls-files`, `git log`, `git rev-parse`, `git status` and `git show`. `git diff`, `git cat-file`, `git grep`, `git blame` and `git archive` are not admitted, so they are already denied `shell-not-allowed`. The class has three members:

1. Object names by path (`<rev>:<path>`, `:<path>`, `:<stage>:<path>`) in any admitted git command. The path part gets the read rules. A colon word that git would resolve differently from a plain split is refused `shell-git-object`: a brace (`@{...}` reflog and date forms, where git splits at the first colon outside braces), an index form starting `:/`, `:!` or `:(` (message search, pathspec magic), or a path starting with `/`.
2. Output forms that print file content: patch, combined diff, word diff, line log (`-L`), pickaxe (`-S`, `-G`), raw and verbose status. `git log` and `git status` take only listed options, compared as whole words, so git's abbreviated long options (`--pat` for `--patch`) and spellings that imply a patch are refused too: an allow-list, not a deny-list. Any other option is `shell-git-output`.
3. `git show` with no operand, a bare revision or an object name. A commit prints its patch. A blob or a tag pointing at a blob prints its content even with `-s`, and the hook cannot tell a blob's hash from a commit's. `git show` therefore takes only object-by-path operands and no option. A bare revision or no operand is `shell-git-object`, and any option is `shell-git-output`.

Design choices (Claude's discretion; no CONTEXT decision governs hook read forms):
- READ_ONLY_COMMANDS keeps all eleven entries; the hook narrows the forms. The generated host settings and the documented count are unchanged, and `git show <rev>:<path>` stays available: GSD's executor agent recommends it for reading another ref, and live sessions used it.
- `git log --stat`, `--shortstat`, `--name-only` and `--name-status` stay admitted, although the verifier's checklist suggested refusing stat output. They print file names and line counts, never content. File names are already listable through `ls` and `git ls-files`. Live attended sessions ran `git log --stat` in 2 of 10 sessions, and a refusal counts toward the 3-denial loop limit. The real-git corpus proves these forms print no sentinel.
- `git show <commit> --stat` is refused; `git log -1 --stat <rev>` gives the same information. `git log` given a blob's hash walks no commit, so it prints nothing; the corpus asserts this with real git.

The rule checks run after the existing read check, so every earlier rule name holds: `shell-git-option` for `--textconv`/`--ext-diff`/`--output`, and `deny-read`/`outside-read-set` for option values.

One residual stays outside the hook and is named, not closed. The run sandbox denies reads by root only (generated settings), so code that a contract command runs can read a tracked secret file in the clone and print it. Closing it would need a sandbox read deny of the clone's secret paths, which can break checks that load such files. That is an owner decision. The proposal docs/containment.md:108 already lists the git-object bypass as remaining; after this fix the code disagrees with that line, which goes to findings.md and is not edited (CLAUDE.md).

Purpose: CR-01 is the one blocking gap in 02-VERIFICATION.md (RC-5, CON-1). The plan is offline only and makes no live model call: nothing is spent against the D-15 ceiling, and offline suites come first as D-07 set. The fresh documentation reviews run as separate processes, as in plans 02-23 to 02-25; their cost is outside the Phase 2 ledger.
Output: the git object and output rules in the hook, unit and real-git integration tests, two RED evidence files, docs/system updates with a fresh review record.
