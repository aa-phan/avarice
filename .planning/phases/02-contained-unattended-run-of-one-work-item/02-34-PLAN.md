<objective>
Close code-review finding R-WR-02 (WR-02; triage group P3, second half). The conventions accept any syntactically valid bare host as a registry host (reproduced: `localhost`, `127.0.0.1`, `169.254.169.254`, `10.0.0.5`, `192.168.1.1`, `intranet`, `2130706433`, `0x7f.1`, `127.1`, `metadata.google.internal`), and the proxy dials the name with no check of the address. Whoever can commit to `.avarice/` can point the sandboxed install at services on the user's machine or LAN, on port 443.

Fix (triage, two layers, because a syntactic refusal alone cannot be complete):
1. The proxy, an adapter that may import node modules, resolves the host itself and refuses the tunnel if any address is not public. It then connects to the vetted address, which also closes DNS rebinding.
2. The conventions refuse the forms that can only mean a local target, written as string rules: src/domain may import neither node:net nor node:path.

The footprint test pins the proxy's network imports to node:http and node:net. The resolver needs node:dns/promises, so that pin changes on purpose. The rule that the proxy is the only listener and stays on the loopback is unchanged.

Test seam (the load-bearing detail, triage): conventions.test.ts pins `127.0.0.1` as accepted, and run-deps.test.ts and allowlist-proxy.test.ts dial loopback servers. `startAllowlistProxy` gains an optional `resolve` that replaces resolution and vetting. Only direct callers of that function can pass it. The EgressProxy port input does not gain it, and AllowlistEgressProxy, the composed proxy, passes only `allow` and `onAttempt`, as the test-only executor seams are kept out of production. run-deps names its registry `registry.avarice.test` and maps it to 127.0.0.1 through the seam. test/containment/npm-ci-proxy.test.ts needs no change: it uses registry.npmjs.org with real DNS, gated by AVARICE_NET=1, and public addresses pass the check.

Reversibility is rated costly: private-network registries become unsupported. See the flagged assumption; the owner checks this in the planning report rather than at a blocking checkpoint, because the change is not one-way.
