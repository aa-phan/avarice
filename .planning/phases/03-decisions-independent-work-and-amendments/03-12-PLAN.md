<objective>
The ledger side of amendments, notifications and cancellation (RC-6, D-19, D-20, AUT-6, AUT-12), on the schema plan 03-02 added. `storeRunContract` needs a lease fence and has no production caller; the amend command is not a lease holder, so it gets an optimistic, version-checked method that writes the whole amendment in one transaction (research Pattern 5, option b). Notifications get their delivery state; a run gets a cancel request the supervisor can read.

Purpose: an amendment is atomic and append-only; notification failures and cancel requests are ledger facts, visible offline.
Output: port and adapter methods, the ntf_ ID prefix, two integration test files.
</objective>
