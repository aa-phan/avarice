## Findings for plan 03-33

Each entry is for plan 03-33 to place in `docs/system/findings.md`; this plan writes none there. Entries 1 to 5 are lines of docs/system that the built code made false and that this plan did not edit (findings.md and unknowns.md belong to plan 03-33). The rest are code-versus-proposal differences or suspected defects met while drafting, with file:line first.

2. `docs/system/findings.md:129`: says no command answers a decision and `resumeRun` only reports a blocked run. `src/cli/commands/decide.ts:1` answers one and `src/app/run-resume.ts` continues a blocked run an answer made continuable. The line is stale.

4. `docs/system/unknowns.md:49` and `:88`: name `failed` and `cancelled` among the states nothing enters, and the decision states as unreachable. `src/app/run-stages/blocked.ts:226` enters `failed` and `src/app/cancel.ts:41` enters `cancelled`.
5. `docs/system/config-reference.md:208` (plan 03-32's document): states a wall clock of 60 minutes per run. The routine preset at `src/domain/run-contract.ts:94` is 120 minutes, with limits that scale per item.
6. `docs/autonomy-and-decisions.md` (quiet hours) against `src/app/notify.ts:114`: the proposal says quiet hours hold everything except blocking notifications. The built code holds every banner in quiet hours, including a blocking one; the inbox still lists the decision.
7. `src/cli/commands/cancel.ts:1`: `avarice cancel` is not in the proposal's CLI table (owner decision of 2026-11-08).
8. `docs/contracts-and-state.md:699` against `src/domain/gates.ts:196`: the proposal states "plan references the contract's acceptance IDs" as a plain G1 rule; the built G1 treats it as an advisory.
9. `src/domain/run-contract.ts:747`: the contract's `notify.digest` list is always empty and nothing reads it. A digest uses the profile's destinations.
10. `src/app/run-stages/schedule.ts:38`: a run is continuable only when it was blocked with reason `decision`. A run blocked for `budget_exhausted` or `enforcement_failure` stays blocked after an amendment answers its decision, because `contract amend` starts no supervisor and `resume` and `decide` apply the same rule. Whether an amendment should continue such a run is for the owner.
11. `src/cli/commands/decide.ts:126`: `decide --wait` follows only a supervisor that this command started. With a live supervisor already holding the lease it returns at once with nothing to follow.
12. `src/app/decide.ts:205`: `decide` reads no run state, so a decision of a run that has failed or been cancelled is still answerable and starts nothing.
13. `src/cli/commands/supervise.ts:66` and `src/app/notify.ts:47`: a supervisor killed after it released the lease of a blocked run and before it raised the banner leaves its queued notice pending. The inbox lists the decision and the next digest covers it.
14. `src/app/run-gsd-config.ts:212`: the resume prompt carries the answer but not the question, since the session remembers asking. The fresh unit that replaces a failed resume carries both.
15. `src/app/run-stages/item.ts:390`: a resumed unit that leaves the parked `WAITING.json` in place, or a parked VERIFICATION that still reads `human_needed`, reads as paused again and opens a new decision. The resume is judged by the classifier against the item base, so a resumed unit that makes no change of its own and writes no records is judged progressed whenever the parked delta carries a SUMMARY and an in-scope change.
16. `src/app/run-stages/item.ts:172`: a stored session ID that is not a UUID makes the item run a fresh unit with no record of why.
17. `src/app/run-stages/item.ts:1786`: gate G3 is always given an empty list of authorized test paths, so the rule that exempts a test path an amendment authorized never applies. The amendment diff is not read for it.
18. Plan 03-61, `src/domain/outcome.ts:116` and `src/app/run-stages/item.ts:390`: a unit that reports `human_needed` only because of a pre-existing required-check failure still pauses. The unit and its verifier are told which checks failed when the item began, and AVARICE never overrides a model-written status. The proposal's unnecessary-escalation metric (`docs/autonomy-and-decisions.md:167`) counts such a pause as an escalation a reviewer could answer from the evidence.
