## Dependency direction and import boundary
- source: /Users/aphan/avarice/docs/architecture.md (section "Dependency direction"; precedence 3)
- type: protocol
- content: `domain` imports nothing outside itself and contains no paths, URLs, SQL, provider names or host APIs (NFR-3). `ports` declare interfaces and capability descriptors and import only `domain` types. `adapters` implement ports and are the only code touching SQLite, filesystem, subprocesses or network. Composition root in `cli` selects adapters from profile configuration. A lint rule (`no-restricted-imports` scoped by directory) fails the build when `domain` or `ports` import an adapter or `node:` modules other than `node:crypto`.

## Process view and lifetimes
- source: /Users/aphan/avarice/docs/architecture.md (section "Process view"; precedence 3)
- type: protocol
- content: No permanent daemon. `avarice` CLI is one command; `avarice supervise <run>` lives until the run reaches `ready_for_review`, `waiting_external`, `blocked_on_decision`, `failed`, `cancelled` or `paused`; contained host invocation (`claude -p` with generated settings, sandbox, hooks) is one GSD unit bounded by wall-clock and cost caps; `avarice hook <event>` runs per tool call with 5 s timeout, fail-closed; `avarice digest` optional via launchd or systemd timer; `avarice dashboard --watch` is a foreground command. Not present on day one: GSD capability `avarice-bridge` (Stage 2), `avarice mcp` stdio server, remote worker, coordination service. AVARICE never calls a model API; every model call happens inside the agent host.

## Trust boundaries TB-1 to TB-7
- source: /Users/aphan/avarice/docs/architecture.md (section "Trust boundaries"; precedence 3)

## Source-of-truth ownership
- source: /Users/aphan/avarice/docs/architecture.md (section "Source-of-truth ownership"; precedence 3)
- type: schema
- content: AVARICE holds references and bounded caches and is never authority for another system's record. GSD owns plans, phases, in-plan tasks, `.planning/codebase/`, `.planning/intel/`, `.planning/graphs/` (AVARICE never writes `.planning/` directly, never patches a stale index). AVARICE ledger is authoritative for project records, checkpoints, attempts, evidence, run contracts, budgets, decision records and its own artifacts. Git/SCM own source code and PR state; CI owns CI results (a re-run creates new evidence); tracker or manual brief owns tickets (a changed ticket moves the run to `blocked_on_decision` reason `ref_changed`); enterprise: SCM/change system/IAM own approvals for privileged actions, personal: run contract or AVARICE approval record; an external denial or revocation overrides any local record. Deployment state out of scope for MVP.

## Enforcement coverage matrix

- type: protocol
- content: AVARICE generates a per-run settings file from the contract in the profile data root (outside every path the run can write) and launches the host headless with flags that make every unanticipated prompt a denial: `--settings`, `--setting-sources ""`, `--permission-mode dontAsk`, `--permission-prompts none`, `--max-budget-usd`, sandbox with `failIfUnavailable` and `allowUnsandboxedCommands: false`, hook `onFailure: "block"` (documented from Claude Code 2.1.295), scrubbed environment. ## Checks and probes run sandboxed
- source: /Users/aphan/avarice/docs/containment.md (section "Checks and probes run sandboxed"; precedence 3)
- type: protocol
- content: Required checks, test-inventory listing and the mutation probe run under the same OS sandbox configuration as the contained invocation, never with the user's full access. Writes limited to the check's working copy and declared artifact paths; reads of credential stores, data root and other profiles denied; network limited to contract endpoints; environment scrubbed. Proposed mechanism `@anthropic-ai/sandbox-runtime` driving Seatbelt/bubblewrap; using it directly from AVARICE is unverified and is a slice 1 spike. If the sandbox cannot start the check is not run, evidence is `unavailable`, G4 cannot pass (CON-3). Mutation probe works in a disposable clone and verifies byte-exact restore per mutant.

## Fail-closed behavior and restricted mode
- source: /Users/aphan/avarice/docs/containment.md (section "Fail-closed behavior", "Restricted mode"; precedence 3)
- type: protocol
- content: Sandbox cannot start -> run `blocked_on_decision` reason `enforcement_failure`. Hook crash/timeout/unreadable policy -> `onFailure: "block"`, hook error path exits 2. Generated settings missing/invalid -> no launch. Host version not admitted or required key unrecognized -> `doctor` reports `restricted`, runs only in restricted mode. Budget ledger unreadable -> all reservations fail. Claude Code hooks fail open by default, so AVARICE depends on `onFailure: "block"` and checks host version before every launch. Restricted mode: `claude -p ... --restricted --settings <run settings> --permission-mode dontAsk --permission-prompts none` against a disposable copy; produces plan, patch file and decision list, never a commit in the user's repository; `status` labels such runs `restricted`.

## File-edit safeguards
- source: /Users/aphan/avarice/docs/containment.md (section "File-edit safeguards"; precedence 3)
- type: protocol
- content: PreToolUse hook denies Edit/Write on an existing file the session has not read and records the digest at read; at edit time a digest mismatch denies ("file changed since read"). New files only under contract `create` globs; deletion only under `delete` globs. Hook resolves `realpath` of target and every parent; `..` and symlinks resolving outside writable paths denied. Generated outputs have declared locations, writable but excluded from the reviewable diff and acceptance evidence. Formatters, generators and package managers allowed only when the contract lists them with paths they may touch; files outside flagged `unexpected_change`, blocking `ready_for_review`. Needed out-of-scope path -> decision class `scope_expansion`, independent work continues.

## Supported unattended workflow scope
- source: /Users/aphan/avarice/docs/autonomy-and-decisions.md (section "Supported unattended workflow"; precedence 3)
- type: nfr

## Decision matrix and authority classes
- source: /Users/aphan/avarice/docs/autonomy-and-decisions.md (sections "Decision matrix", "Authority classes in the contract"; precedence 3)
- type: protocol
- content: Supervisor classifies every human-involvement situation by structural signals first (GSD checkpoint type and gate, policy result, budget state, gate result, contract decision classes), never model confidence alone (AUT-1). Rows: answer available in code/docs -> investigate, no human; routine reversible choice inside scope (`delegated`) -> proceed, log assumption if it affects the diff; low-impact ambiguity with authorized default -> apply default, record as assumption shown first in review summary; consequential ambiguity -> open decision record, block dependent work, continue independent; architecture change beyond delegated authority (GSD Rule 4, new dependency, schema change, public API change, out-of-scope path, surviving AUT-17 or FR-25 finding) -> decision class `scope_expansion` or `architecture`; missing permission -> block operation, never infer permission; verification failure within repair budget -> autonomous repair in a new GSD unit; possible equivalent mutant -> decision only the user can accept; repeated failure, contradictory evidence or exhausted budget -> checkpoint and escalate with smallest reproducer. Unclassifiable GSD pause is treated as consequential, never answered with first option or "yes". Authority classes: `delegated` (agent within conventions), `default` (contract's stated default, recorded as assumption), `human` (user or policy-named authorizer), `prohibited` (nobody inside the run). No universal "approve the plan" gate (FR-13).

## Operational states and cancellation
- source: /Users/aphan/avarice/docs/autonomy-and-decisions.md (section "Operational states"; precedence 3)
- type: protocol
- content: Supervisor running only in `running` and `verifying`; not running in `waiting_external`, `blocked_on_decision`, `ready_for_review`, `failed`, `cancelled`, `paused`. Cancellation sends SIGTERM to the current invocation (host exits 143, kills Bash process tree), records in-flight remote calls as `sideEffect: unknown`, leaves the worktree intact. Resumption re-reads the ledger, refreshes external state, starts at the next action in the last checkpoint. Deadlines and silence never approve anything (AUT-4); before resuming the supervisor refreshes tickets, base branch, policy files and credential validity.

## Standard Result and PortError contract
- source: /Users/aphan/avarice/docs/contracts-and-state.md (section "Shared conventions"; precedence 3)
- type: api-contract
- content: Every port method returns `Result<T> = { ok: true; value } | { ok: false; error: PortError }`; adapters never throw across a port boundary and never return success for something they did not do (FR-16). PortError kinds: unsupported (capability, reducedMode), denied (rule, enforcer in host|external-platform|avarice), unauthenticated (credentialRef, recovery), not_found, conflict (expected, actual), unavailable (retryAfterMs, cause), timeout (afterMs, sideEffect none|unknown), cancelled (sideEffect), invalid (field, reason), internal (cause). `sideEffect: 'unknown'` triggers reconciliation (`TaskSource.findByKey` or `ChangeRequests.findByHead`) before any retry (NFR-7). Retry eligibility per kind is tabled in the source (unavailable: yes with backoff; denied/not_found/invalid/internal/unsupported: no; unauthenticated: after user re-authentication, run `blocked_on_decision` reason `unauthenticated`).

## Run state machine and recovery rules
- source: /Users/aphan/avarice/docs/contracts-and-state.md (sections "Run state machine", "Recovery rules"; precedence 3)
- type: protocol
- content: Run states (single list): contract_ready, running, waiting_external, blocked_on_decision, verifying, ready_for_review, awaiting_review, closed, failed, paused, cancelled. `blocked_on_decision` reason codes: `decision`, `enforcement_failure`, `budget_exhausted`, `unauthenticated`, `ref_changed`, `ref_deleted`, `access_revoked`. Work item states: ready -> delegated -> implemented -> gated -> done (or `blocked_on_decision`). Guards: contract_ready->running needs valid contract, host enforcement `enforced`, worktree on `baseRevision`, budget rows; item delegated->implemented needs outcome `progressed`, HEAD moved, GSD VERIFICATION `passed`; implemented->gated needs G2; gated->done is one `transition` transaction recording the item's revision commit; verifying->ready_for_review needs G4 on the final revision; ready_for_review->awaiting_review needs contract authorization, AVARICE push outside the contained invocation, PR reference recorded. Interrupted runs become `paused` with evidence from the interrupted step `inconclusive`; crashed invocation with no external side effect is discarded by resetting the worktree to the item's last checkpoint commit (CON-16), retried once if budget allows, then escalated; ambiguous PR creation pauses until reconciled via `findByHead`. Full tables in source.

## Phase gates G0 to G4
- source: /Users/aphan/avarice/docs/contracts-and-state.md (section "Phase gates"; precedence 3)
- type: protocol
- content: G0 contract (before running): schema valid, every acceptance criterion has at least one `verifiedBy`, required checks exist in repository config, host enforcement `enforced`. ## Mutation evidence verdicts
- source: /Users/aphan/avarice/docs/contracts-and-state.md (section "Mutation evidence"; precedence 3)
- type: schema
- content: One `mutation` evidence row per probe pass; per-mutant verdicts in the mutant matrix artifact. Row status `passed` when every mechanical mutant KILLED or accepted as equivalent; `failed` when any SURVIVED; `inconclusive` when any NO-RUN and none SURVIVED; `unavailable` when the pass could not be trusted (probe exit 2: baseline red, restore failed, config unreadable; no verdicts, blocks G4).
