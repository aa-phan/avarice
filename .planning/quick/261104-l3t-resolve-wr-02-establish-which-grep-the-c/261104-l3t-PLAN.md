<objective>
Resolve review WR-02 and the last "missing" item of 01-VERIFICATION.md gap P-3. Remove `grep` from READ_ONLY_COMMANDS so that every shell grep is denied `shell-not-allowed` by name, whichever binary the contained shell would run. Searches go through the Grep tool, whose root the hook already judges. Then delete the grep option model, which no production policy can reach. Close the matching gap the same investigation found in the other shimmed command (bfs `find -rm`). Make the docs/containment.md CON-1 row state exactly what remains.

Decision: option (b), drop grep. Reasons, from what was observed at planning time (HEAD 974d8b1, Claude Code 2.1.318):
1. There is no single grep to model. In the host's Bash tool, `grep` is a shell function from the shell snapshot. It runs the ugrep embedded in the claude binary by default. When the arguments contain ugrep's filter, pager, view, config, save-config, `-z`/`-Z` or `--null` options, it falls back to `command grep`, which is /usr/bin/grep (BSD 2.6.0-FreeBSD). So one shell picks between two implementations per call. That choice is a Claude Code implementation detail that can change with any update.
2. Option (a) is large and cannot be proven. Establishing the contained shell's grep needs a paid live contained run, repeated after every host update. Hardening for both implementations would also mean modelling ugrep's option surface: `-NUM` depth recursion, reading files directly inside a directory operand without `-r`, `-d dereference-recurse`, and `--filter`, which runs commands. That comes on top of BSD and GNU syntax.
3. Option (b) is a one-line production change, and reading the code proves it. In checkSegment (src/domain/hook-decision.ts:471-472), a segment whose words match no readOnly entry returns `shell-not-allowed` before any option is parsed. The binary that would have run never matters.
4. Nothing observed is lost. Every shell grep in the three recorded live runs (test/containment/live-run-*.jsonl) was already denied `shell-syntax`, because of `2>/dev/null` and unquoted globs. The GSD map-codebase secret-scan grep line is denied for the same reasons. IN-01 already routes staging searches to the Grep tool, and the settings allow `Grep` (src/adapters/host-claude/settings.ts:89).

The dead-code deletion (Task 2) is not needed to close the bypass. It keeps the hook from carrying an incomplete grep model, which a later re-admission of grep would silently bring back. It also keeps the docs honest.

Adjacent finding included by the same reasoning (CON-2). The same snapshot defines `find` as the embedded bfs. bfs accepts `-rm`, an alias of `-delete`, and FIND_DENIED_ACTIONS does not list it. `find . -rm` is `allow:shell-identity` today. The sandbox limits the deletion to the write roots, and the staging diff detects it, but a command the hook admits as read-only must not delete. Adding the one entry is in scope because the docs row must state what the substituted tools can do.

Output: one production line in READ_ONLY_COMMANDS plus one in FIND_DENIED_ACTIONS; a smaller hook-decision.ts; tests that pin each grep form and `-rm`; a truthful CON-1 row and command row; evidence in the SUMMARY.
</objective>
